# Homeschool Design System

A consistent, accessible design language for the Homeschool app across desktop and mobile platforms, powered by design tokens and a unified component library.

## Design Philosophy

The Homeschool app uses a **warm, approachable, and educational** design language that feels friendly to families while maintaining clarity and professionalism for tracking academic progress.

### Core Principles

1. **Clarity First** - Information should be immediately scannable
2. **Student-Centric Colors** - Each child has a distinctive color for easy identification
3. **Encouraging Tone** - Success states use warm, positive colors
4. **Accessible** - WCAG AA compliant contrast ratios
5. **Consistent** - Same patterns on desktop and mobile
6. **Token-Based** - Single source of truth for design values

## Getting Started

### For New Components

Always use components from the design system library:

```tsx
import { Button, Card, Badge, Input, Modal, Alert } from '@/components/ui'

// ✅ Good
<Button variant="primary">Save Changes</Button>
<Card><p>Content here</p></Card>

// ❌ Bad - Don't create custom styled buttons
<button className="bg-fuchsia-500 text-white px-4 py-2 rounded-lg">Save</button>
```

### Design Tokens

All design values (colors, spacing, typography) are defined in `design-tokens.json` and automatically generated for both desktop (Tailwind) and mobile (React Native).

**Using tokens in Tailwind:**
```tsx
// ✅ Use design system tokens
<div className="bg-brand-primary text-neutral-text">
<button className="bg-status-success hover:bg-status-success-dark">

// ❌ Don't use arbitrary color values
<div className="bg-[#d946ef]">
```

**Using tokens in mobile:**
```tsx
import { useColors } from '@/theme/ThemeContext'

function MyComponent() {
  const colors = useColors()
  return <View style={{ backgroundColor: colors.primary }} />
}
```

## Components

### Button Variants

- **Primary**: Main actions (fuchsia background)
- **Secondary**: Alternative actions (gray background)
- **Outline**: Tertiary actions (border only)
- **Ghost**: Minimal actions (no background)
- **Danger**: Destructive actions (red)

### Button Sizes

- **sm**: 32px height, 12px padding
- **md**: 40px height, 16px padding
- **lg**: 48px height, 20px padding

### Card Patterns

Cards are the primary container for content groupings:

- White background
- 12px border radius
- 1px border in `#e5e7eb`
- Subtle shadow
- 16-24px padding

### Badge Patterns

Badges indicate status or categorization:

- Rounded (4px radius)
- Small padding (6-8px horizontal, 2-3px vertical)
- Medium font weight
- Pastel background with dark text

## Accessibility

- All interactive elements have visible focus states
- Color contrast meets WCAG AA (4.5:1 for text)
- Touch targets are minimum 44x44px on mobile
- Icons have aria-labels when used alone
- Form inputs have associated labels

## Animation

- Use `duration-200` for most transitions
- Use `duration-300` for larger state changes
- Prefer `ease-out` for entering, `ease-in` for leaving
- Respect `prefers-reduced-motion`

## Deprecated Patterns

### ⚠️ Legacy CSS Classes (Deprecated)

The following CSS classes are **deprecated** and will be removed in a future version:

- `.btn`, `.btn-primary`, `.btn-secondary`, etc. → Use `<Button />` component
- `.card`, `.card-hover`, `.card-interactive` → Use `<Card />` component
- `.badge`, `.badge-*` → Use `<Badge />` component
- `.input`, `.label` → Use `<Input />` component or Tailwind utilities

**Migration Example:**

```tsx
// ❌ Deprecated
<button className="btn btn-primary">Save</button>
<div className="card">Content</div>
<input className="input" />

// ✅ Current
<Button variant="primary">Save</Button>
<Card>Content</Card>
<Input />
```

### ⚠️ Hardcoded Colors (Deprecated)

Don't use hardcoded Tailwind color classes:

```tsx
// ❌ Deprecated - hardcoded colors
<div className="bg-fuchsia-500">
<span className="text-blue-600">

// ✅ Current - design system tokens
<div className="bg-brand-primary">
<span className="text-student-blue-500">
```

## Contributing

When adding new components or patterns:

1. **Check the token system** - Use existing design tokens from `design-tokens.json`
2. **Follow naming conventions** - Use semantic names, not visual descriptions
3. **Document in Storybook** - Add stories showing all variants and states
4. **Test accessibility** - Verify keyboard navigation and screen readers
5. **Cross-platform** - Ensure mobile parity when applicable

See `DESIGN_SYSTEM.md` for comprehensive migration and contribution guidelines.
